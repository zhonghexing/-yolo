## 1. 项目背景

### 1.1 行业背景

在现代制造业中，螺丝作为最基础的紧固件，广泛应用于汽车、航空航天、电子设备、建筑等领域。据统计，一辆普通汽车需要使用约3000个螺丝，一个智能手机内部也有数十个微型螺丝。螺丝的质量直接影响最终产品的安全性和可靠性。

传统的螺丝质量检测主要依赖人工目视检查，存在以下问题：

| 问题 | 描述 | 影响 |
|------|------|------|
| 效率低下 | 人工检测速度有限，每小时仅能检测200-500个 | 产能瓶颈 |
| 主观性强 | 不同检测人员标准不一致 | 质量波动 |
| 疲劳误差 | 长时间工作导致漏检率上升 | 质量风险 |
| 成本高昂 | 需要大量质检人员 | 人力成本 |
| 数据缺失 | 无法记录和追溯检测数据 | 管理困难 |

### 1.2 技术背景

随着深度学习和计算机视觉技术的快速发展，基于AI的自动化视觉检测已成为工业质检的重要发展方向：

- **深度学习目标检测**：YOLO系列、Faster R-CNN等算法在工业检测中广泛应用
- **边缘计算**：NVIDIA Jetson、Intel OpenVINO等平台支持边缘部署
- **高分辨率成像**：工业相机分辨率和帧率不断提升
- **5G/物联网**：为工业视觉系统提供高速数据传输

### 1.3 竞赛背景

本项目参加"基于AI视觉的行业应用创新赛"，竞赛要求参赛团队针对特定行业场景，开发基于AI视觉的创新应用解决方案。

**竞赛主题**：工业螺丝缺陷检测

**竞赛目标**：
- 开发高精度的螺丝缺陷检测系统
- 实现多种缺陷类型的自动识别与分类
- 构建可实际应用的桌面演示系统

|--------|------|------|
| **Must** | 必须实现 | 系统核心功能，不满足则项目失败 |

## 3. 功能需求

### 3.1 核心功能需求

#### FR-001: 图像采集与输入

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-001 |
| 需求名称 | 图像采集与输入 |
| 优先级 | Must |
| 描述 | 系统应支持多种图像输入方式 |

**功能要求**：
1. 支持从本地文件夹批量导入图像（JPG、PNG、BMP格式）
2. 支持拖拽方式导入图像
3. 支持单张图像导入进行实时检测
4. 图像分辨率支持：640×640 至 4096×4096
5. 自动进行图像预处理（尺寸调整、格式转换）

**输入**：螺丝图像文件或文件夹路径
**输出**：预处理后的图像数据

#### FR-002: 缺陷检测与识别

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-002 |
| 需求名称 | 缺陷检测与识别 |
| 优先级 | Must |
| 描述 | 系统应能准确检测和识别螺丝缺陷 |

**功能要求**：
1. 支持检测以下6种类型：
   - 正常件（Normal）
   - 轻微划痕（Minor Scratch）
   - 严重划痕（Severe Scratch）
   - 缺角（Missing Corner）
   - 变形（Deformation）
   - 混料（Mixed Material）
2. 检测准确率≥95%
3. 支持单张图像中多个缺陷的同时检测
4. 输出缺陷的位置（边界框坐标）
5. 输出缺陷的类别和置信度

**输入**：预处理后的螺丝图像
**输出**：检测结果（类别、置信度、边界框）

#### FR-003: 结果可视化

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-003 |
| 需求名称 | 结果可视化 |
| 优先级 | Must |
| 描述 | 系统应直观展示检测结果 |

**功能要求**：
1. 在原图上绘制检测框和类别标签
2. 使用不同颜色区分不同缺陷类型
3. 显示检测置信度百分比
4. 支持结果图像的放大、缩小、平移查看
5. 缺陷区域高亮显示

**颜色方案**：

| 缺陷类型 | 颜色 | 色值 |
|----------|------|------|
| 正常件 | 绿色 | #00FF00 |
| 轻微划痕 | 黄色 | #FFFF00 |
| 严重划痕 | 橙色 | #FF8C00 |
| 缺角 | 红色 | #FF0000 |
| 变形 | 紫色 | #8B008B |
| 混料 | 蓝色 | #0000FF |

#### FR-004: 批量检测

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-004 |
| 需求名称 | 批量检测 |
| 优先级 | Must |
| 描述 | 系统应支持批量图像检测 |

**功能要求**：
1. 支持选择文件夹进行批量检测
2. 显示批量检测进度（进度条、已处理/总数）
3. 20个样本在180秒内完成检测（实际目标<30秒）
4. 批量检测过程中支持暂停和取消
5. 批量检测完成后汇总统计结果

#### FR-005: 检测报告生成

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-005 |
| 需求名称 | 检测报告生成 |
| 优先级 | Should |
| 描述 | 系统应能生成检测报告 |

**功能要求**：
1. 生成包含以下信息的检测报告：
   - 检测时间、检测数量
   - 各类缺陷数量统计
   - 合格率/不良率
   - 典型缺陷图像示例
2. 支持导出为CSV、Excel、PDF格式
3. 支持查看历史检测记录

### 3.2 辅助功能需求

#### FR-006: 模型管理

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-006 |
| 需求名称 | 模型管理 |
| 优先级 | Should |
| 描述 | 系统应支持模型的加载和切换 |

**功能要求**：
1. 支持加载不同版本的检测模型
2. 显示当前模型信息（版本、精度、参数量）
3. 支持模型热切换（无需重启应用）

#### FR-007: 检测参数配置

| 属性 | 描述 |
|------|------|
| 需求编号 | FR-007 |
| 需求名称 | 检测参数配置 |
| 优先级 | Could |
| 描述 | 系统应支持检测参数的调整 |

**可配置参数**：

| 参数 | 说明 | 默认值 | 范围 |
|------|------|--------|------|
| conf_threshold | 置信度阈值 | 0.5 | 0.1-0.9 |
| iou_threshold | IoU阈值 | 0.45 | 0.1-0.9 |
| max_detections | 最大检测数 | 100 | 1-1000 |
| img_size | 输入图像尺寸 | 640 | 320-1280 |
